## Research: modding architecture (done)
Layers: (1) data/prototype (Factorio data/updates/final-fixes 3-round patch, SC2 child-overrides inheritance, schema validation, merged-data hash) (2) declarative trigger/effect (Paradox/SC2; ~90% of campaign scripting; editor emits it) (3) sandboxed synced script runtime (Recoil gadgets; event-driven, nth-tick, per-mod instruction budgets, state only in declared serialisable store) (4) unsynced UI layer (widgets; read-only, commands via input stream).
Mod rules: no time/IO/OS/load; declared store + heavy-mode save/reload hash check; sim-owned seeded RNG; no floats in sim API; sorted-id iteration; instruction (not time) budgets; unsynced never writes sim; same mod list + data hash.
VM options: gilzoide lua-gdextension (Lua 5.4, ints, active; no budgets documented → custom count-hook + allocator GDExtension), Luau GDExtension (best sandbox primitives, doubles only), Wasm (strongest isolation, needs toolchain), godot-sandbox RISC-V. Avoid archived godot_luaAPI, godot-luau-script.
Early decisions: VM choice; fixed-point everywhere + deterministic trig; trigger vs script split & versioned event API; mod state/save/replay checkpoint+hash cadence; ranked mod policy; VM per battle vs shared, cross-battle visibility; manifest/deps/load order, campaigns-as-mods; desync tooling before mod API.

## Research: sim-core performance (done; bench in scratchpad/bench, gobench)
gecs v7.0.1: Entity/World/System are Nodes, Components are Resources, archetype columns of object refs, global ECS.world singleton (no clean multi-world / threaded battles), no determinism features.
ms/tick (both sides, fixed-point int, grid targeting, no pathfinding): 2,000 models → GDScript SoA 7.9 · RefCounted 8.8 · gecs iterate ~11-13.6 · gecs idiomatic ~16-18.5 · Go native 0.33 (≈24x faster than GDScript SoA). Spatial query/targeting dominates, not ECS layer. Heavy case 4 battles×1,200 → SoA ~16 ms/tick; at placeholder 300 ticks/turn ≈ 4.7 s CPU (native ≈0.2 s). Pathfinding not included.
Recommendation: drop gecs as sim core (maybe campaign/UI only); start GDScript SoA BattleSim (RefCounted, no Nodes/floats, own PRNG, state hash, step(orders)->events / snapshot() interface) so native core (Rust/C++ GDExtension, Lua embedded via mlua/sol2) can swap in; decide via spike (real loop incl. pathfinding/LOS/deaths at 600/side, threading 4-6 sims on WorkerThreadPool, MultiMesh snapshot cost, Lua hook cost, native toolchain friction — no cargo/gcc installed).

## Research: Slay the Spire modding (done, haiku)
StS1: ModTheSpire loader + BaseMod content API + SpirePatch bytecode patches (break on updates); jar + ModTheSpireInfo.json; Workshop since 2019 with "vanilla vs modded" launch choice.
StS2 (Godot, C#): mods = C# DLL + .pck assets + manifest.json; Harmony patching; BaseLib/ModConfig deps; official Workshop since June 2026 (~420 mods at launch); "Play with Mods" launch; first-run untrusted-code warning, no sandbox; separate modded saves; achievements off with mods; co-op needs same mods/order.
Godot: load_resource_pack (pck/zip; replaces same paths by default; load in autoload _init); packs can contain scripts → security risk; sign official packs.
Takeaways: data-first schema-validated mods; manifest (id, version, target API, deps) refuse on mismatch; hard official/modded line (separate saves, badge, no ranked/achievements with mods); record mod list in replays; no code mods in v1 (no internal patching); Workshop subscribe + Steam Cloud sync; reject packs with scripts/DLLs; if code later: explicit opt-in warning + signed official packs.

## Research: data-oriented ECS and "archetypes" (round 5, from memory of primary docs, unbenchmarked)
- Two meanings: ECS "storage archetype" = table of entities with an identical component set (flecs, Bevy, DOTS); designer's "archetype" = template/prefab (flecs prefabs with IsA + per-instance override, Bevy bundles/scenes, Unity prefabs, SC2 parent/child catalogs). They are orthogonal.
- flecs prefabs: shared components by reference, write → private override; variants = prefab IsA prefab. Same semantics can be resolved offline: parent → child → overrides flattened at load.
- Storage: archetype tables (fast iteration, slow add/remove), sparse sets (EnTT; O(1) add/remove), plain SoA per entity kind (simplest; best for fixed schemas). Status effects decide it: as structural components they cause table churn → make them columns/bitmasks or a separate effects store. In GDScript only Packed*Arrays are fast; Objects/Dictionaries/untyped Arrays slow; hand-written archetype tables not worth it at this scale.
- Determinism: explicit fixed system order; stable iteration (rows or sorted IDs, never hash order); deferred structural changes via command buffer applied at phase end; sim-owned RNG with fixed draw order; integer/fixed-point state; per-tick hash.
- Multiple worlds (flecs worlds, Bevy SubApps, DOTS Worlds): isolation, cheap create/free per battle, per-battle hash/replay, one battle per thread, headless single-battle tests. Costs: explicit transfer messages (reinforcements), shared immutable template store. In GDScript a "world" is just a BattleState object.
- GDScript store sketch: per-kind SoA columns, 64-bit generational IDs, slot→row table, free list, swap-remove, command buffer; ~200–300 lines. Alternatives (Godex, flecs bindings, bevy_godot4) unverified/not better at this scale.
- Recommendation: templates for authoring (JSON parent/overrides resolved once into an immutable TemplateTable, cycle checks, provenance), flat SoA runtime per BattleState/OverworldState, fixed system order, command buffer, fixed-point, seeded RNG, state hash. Decisions: naming; inheritance depth (≤3); copy-at-spawn vs live inheritance; status effects as columns vs general store (modder-added effects → general); float vs fixed (fixed); replay/desync policy; measurable trigger for going native.

## Research: serverless P2P netcode (round 5; several items from memory, verify)
- Transport: Steam Networking Sockets + Steam Datagram Relay (Valve-relayed P2P, hides IPs; no per-GB fee per memory, verify in Steamworks). Steam lobbies free (owner migration built in). GodotSteam (now on Codeberg) supports Godot 4.x; Godot 4.7 build availability unverified (biggest integration risk). Use its messages/sockets API directly with own packet format. EOS P2P (free relay, cross-store, weaker Godot support). ENet: no NAT traversal. WebRTC: needs own signaling + paid/self-hosted TURN.
- Comparables: BAR = central lobby (Teiserver) + SPADS autohosts + replay/leaderboard API (not serverless). HotA = lobby matches players, host is a player (relay unverified). Factorio = no host migration. AoE2 DE = lockstep with fragile host migration. Frozen Synapse / Combat Mission = WeGo orders + deterministic local resolution, no migration.
- Host migration: easy in lockstep (all peers hold state + inputs); deterministic successor (lowest ID or seeded rotation); every peer keeps this turn's orders; epoch numbers prevent split brain; deadlines as turn-start timestamp + duration; versioned snapshots for rejoin. Cheating host can delay/drop orders and read fog, not alter results without hash mismatch.
- Rollback unnecessary for 60 s planning WeGo; prediction useful only for local previews/validation, pending→locked order UI, local resolution + end-of-turn hash compare. Recommendation: plain per-turn lockstep + previews.
- Ranked: Steam leaderboards are client-writable (display only). Free-tier serverless (e.g. Cloudflare Worker + D1) does Glicko-2, verifies Steam auth tickets, accepts results co-signed by all peers; headless auditor re-simulates sampled/disputed replays (catches falsified outcomes, not bots or collusion).
- Decisions: fog/hidden info stance; Steam-only vs transport abstraction; host rotation purpose; ranked anti-cheat stance; rating trust boundary (serverless vs Steam-only); disconnect rules (reconnect window, AI takeover/forfeit, rated result).

## Research: effect languages (effect-language interview, sw-p2q.1, 2026-11-10)
Sources: RePoE docs (stat_translations.md, mods.md), PoB modSyntax.md / addingMods.md / ModStore.lua / Global.lua, GGG forum (Mark_GGG on increased vs more, thread 892570), poedb.tw trigger supports, s2editor-guides, Elfansoer Dota Lua wiki, tranek GASDocumentation + Epic GAS docs. poewiki.net was bot-walled; PoE wiki facts came via search snippets.
- PoE stores mods as stat IDs + values; a separate translation table renders text (variants by value range, negate handlers, hidden stats). Mods: domain, prefix/suffix, groups (one per group), spawn weights by tag.
- Increased/reduced = one additive pool per stat; more/less = separate multipliers. "Damage taken" is its own pool (after mitigation). Wording is kept strict because players confuse the two.
- Conversion: fixed one-way order in PoE1 (Phys->Light->Cold->Fire->Chaos), "at most once" in PoE2; gained-as-extra before conversion; conversion after flat, before increased/more.
- Support compatibility is gated by HIDDEN skill types, not visible tags: a major opacity complaint.
- Triggers: each skill one trigger; cooldowns (Cast On Crit 0.15 s), fixed intervals (Cast while Channelling), per-skill exclusion lists, and PoE2 anti-self-chain rules. Loops are policed by hand.
- Stacking varies per ailment (ignite: many instances, only highest deals damage; curses: limited count). Different buff types don't interact.
- PoB: mod(name, type BASE/INC/MORE/OVERRIDE/FLAG/MAX/MIN/LIST, value, source, flags, tags). Flag masks AND, keyword masks OR. Tag types: Condition, ActorCondition, Multiplier (with limits), PerStat, StatThreshold, SkillType, GlobalEffect, DistanceRamp. Rounding is scattered across tag handlers. It parses display text with a ~672k-char pattern parser and must keep old wordings forever: the cost of text-as-source.
- SC2 data editor: effect trees (Set, Search Area, Apply Behavior, Persistent, Switch), validators as reusable predicates; powerful but deep, hard to trace, no generated descriptions.
- Dota 2: fixed vocabulary of modifier properties and boolean states, events; default refresh vs MULTIPLE instances; logic in arbitrary Lua (not sandboxed, not self-describing).
- Unreal GAS: Base vs Current value; ops Add, Multiply, Divide, Override -> ((Base+Add)*Mul)/Div, override last; multipliers ADD by default (1.5x + 1.5x = 2x), newer compound op; magnitudes from tables, attribute-based, custom calcs, set-by-caller tags; hierarchical gameplay tags; stacking per source/target with limits and refresh/expiry policies; execution calcs are opaque C++.
- Lessons: one canonical operator order with centralised rounding; a termination rule for conversion; explicit trigger budgets; structured data -> generated text, never the reverse; no hidden stats or types; pool modifiers by stat + tag masks and cache by condition state.
